# Favourite venues + Concerts shows concerts at other venues

**Mode:** A, bug verification. I did a static review of `EventsQuery.swift` and `api-notes.md` only. I had no device, no build, no git history and no backend, so I did not reproduce anything on screen and did not call the API.

## Short answer

Yesterday's fix ("Don't send id 0 to the events API") is very likely what causes this bug. It deletes every venue whose id is 0 without saying so. The venues endpoint currently returns some real venues with `id: 0`, because they have no venue page in the CMS. If both of the user's favourite venues are among them, the app sends `venue_ids: []`. The API treats an empty array as "no venue filter", so it returns every concert. That is the screen the user describes. "Only Concerts works" fits too: the category filter is sent unchanged, and the venue filter quietly disappears.

### Why yesterday's fix caused this

The earlier bug was probably that the app sent `0` and the API failed or matched nothing. Yesterday's fix only treated the symptom: it removes the value the user chose. An empty filter means "any", so the request got broader instead of narrower (skill patterns: *empty filter means "any"*, *silent drop*, *sentinel ids colliding*).

## Proposed fix

### 1. Backend/CMS (root cause of the data). Owner: backend/CMS team
Every venue the API returns must have a unique, stable, non-zero id, even when it has no venue page. Until then, venues with id 0 cannot be filtered at all, and each of them looks like "No favourite venue" in the app.

### 2. App: stop silently widening the query and separate the sentinel
Review gate:
- *Does it drop or hide a user choice?* It no longer drops them silently. Unresolvable venues are surfaced so the UI can say so, and we never send an empty filter when the user did pick venues.
- *What does empty mean?* "Any venue". So we send `[]` only when the user really chose "no favourite venue" or picked nothing.
- *Changed cells:* rows 2 and 3 now give an honest result. Rows 1, 4 and 5 are unchanged.
- *Backend change needed:* yes (item 1).

### 3. Regression tests (XCTest)

```swift
func testAllPickedVenuesUnfilterable_doesNotQueryAllVenues() {
    let q = EventsQuery(favouriteVenues: [Venue(id: 0, name: "A"), Venue(id: 0, name: "B")],
                        categories: [.concerts])
    XCTAssertNil(q.body())                       // before the fix: ["venue_ids": []] -> all concerts
    XCTAssertEqual(q.unfilterableVenues.count, 2)
}

func testMixedVenues_sendsValidAndReportsRest() {
    let q = EventsQuery(favouriteVenues: [Venue(id: 12, name: "A"), Venue(id: 0, name: "B")],
                        categories: [.concerts])
    XCTAssertEqual(q.body()?["venue_ids"] as? [Int], [12])
    XCTAssertEqual(q.unfilterableVenues.map(\.name), ["B"])
}

func testNoFavouriteVenue_meansAnyVenue() {
    let q = EventsQuery(favouriteVenues: [], categories: [.concerts])
    XCTAssertEqual(q.body()?["venue_ids"] as? [Int], [])
}

func testValidVenues_unchanged() {
    let q = EventsQuery(favouriteVenues: [Venue(id: 3, name: "A"), Venue(id: 7, name: "B")],
                        categories: [.concerts])
    XCTAssertEqual(Set(q.body()?["venue_ids"] as? [Int] ?? []), [3, 7])
}
```
