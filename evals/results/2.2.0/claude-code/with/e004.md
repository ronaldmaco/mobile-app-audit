# App Review rejection "app does not open": analysis and resubmission plan

**Mode:** E (store readiness after a rejection), plus the root-cause and impact-map steps from bug verification (2.4, 2.5), because the rejection is a launch failure.

**Bottom line:** The most likely cause is the toolchain change, not your code. The rejected build was made with the newest Xcode and iOS SDK. The app still uses the old app-delegate-only lifecycle: there is no `UIApplicationSceneManifest` and no `SceneDelegate`. Apple said that after iOS 26, UIKit apps built with the latest SDK must adopt the UIScene lifecycle **or they will not launch**. Your phone runs last month's build, which was made with the previous Xcode, so the new requirement does not apply to it. That is why it "works on my phone". This is a **Suspected** cause backed by strong code evidence. I could not reproduce it because I have no device, simulator or crash log.

The fix is small and does not change the design: adopt the scene lifecycle and move the social-login URL callback to the scene delegate. If you don't move it, launch will work but social login will break silently.

## 1. What I checked (evidence)

| File | Observation |
|---|---|
| `notes.md:1` | Rejected build = newest Xcode + iOS SDK. Last month's build = previous Xcode. The only known difference between the two builds is the toolchain. |
| `Info.plist:2-6` | `UIMainStoryboardFile = Main` and **no `UIApplicationSceneManifest`**, so the app uses the legacy app-delegate lifecycle. |
| `AppDelegate.swift:1-7` | `var window: UIWindow?` on the app delegate. There is no `SceneDelegate`, no `application(_:configurationForConnecting:options:)`, and the URL callback is only in `application(_:open:options:)`. |
| `AppDelegate.swift:4-6` | The social-login redirect (`sociallogin-demo://`, `Info.plist:5`) is handled **only** by the app-delegate method. iOS does not call that method once the app uses scenes. |

**Why "works on my phone" proves nothing here:** you ran a different binary, built with an older SDK and probably signed for development, on your own OS version. App Review ran the new binary on the newest iOS. (Skill section 2.10: "old build" is the first reason a bug "is not there".)

### Root cause chain
New SDK at link time → UIKit requires the UIScene lifecycle for apps linked against it → `Info.plist` has no scene manifest → the app fails at launch (it never shows a window), which App Review reports as "the app does not open".

### Status
- Cause: **Suspected (high confidence)**. To make it **Verified**, someone has to do one of the steps in section 5 (crash log from the rejection, or a launch on the newest simulator with the submission toolchain).
- Other reasons for "does not open" that I cannot rule out from these files (none are visible in the fixture): a crash in `SocialLogin` SDK init with the new SDK, a removed or changed API, a missing privacy manifest, or a backend or geo block on the first screen. The crash log will settle this.

## 2. Impact map (before writing the fix)

| Axis | Cell | Expected after fix | Risk if done badly |
|---|---|---|---|
| Launch | Cold launch, newest iOS, new SDK | Main storyboard's first screen appears | Black screen if the storyboard is not wired to the scene |
| Launch | Cold launch, oldest supported iOS | Same as above | Scene APIs need iOS 13+. Check the deployment target |
| Social login | App **running**, user returns from the provider via `sociallogin-demo://` | `SocialLogin.shared.handle(url)` is called and login completes | Login silently does nothing: `application(_:open:options:)` is no longer called |
| Social login | App **killed** during the provider flow, cold start from the URL | URL is handled from `connectionOptions.urlContexts` | Same silent failure. This is the most common miss |
| Social login | Unknown or malformed URL | `handle` returns false and nothing crashes | n/a |
| Other app-delegate code | Any `window` use, `applicationDidBecomeActive` / `WillResignActive` / `DidEnterBackground`, root VC swaps | Moved to the matching `scene...` callbacks | These callbacks no longer fire under scenes. The fixture only shows the URL handler; **search the full project for `window` and `applicationDid`/`applicationWill`** |
| Sibling | Other targets (extensions, other apps sharing this code) built with the new SDK | Same migration | Same launch failure |

## 3. Proposed fix (diffs, not applied)

Review gate (2.5):
- Does it drop or hide any user choice or server value? No. Every URL that was handled before is still handled, plus the cold-start path.
- Does it change the design? No. Same storyboard, same first screen, same navigation.
- Backend change needed? No.

### 3.1 `Info.plist`: declare the scene manifest

```diff
 <plist version="1.0"><dict>
   <key>CFBundleShortVersionString</key><string>3.0</string>
   <key>UIMainStoryboardFile</key><string>Main</string>
   <key>CFBundleURLTypes</key><array><dict><key>CFBundleURLSchemes</key><array><string>sociallogin-demo</string></array></dict></array>
+  <key>UIApplicationSceneManifest</key>
+  <dict>
+    <key>UIApplicationSupportsMultipleScenes</key><false/>
+    <key>UISceneConfigurations</key>
+    <dict>
+      <key>UIWindowSceneSessionRoleApplication</key>
+      <array>
+        <dict>
+          <key>UISceneConfigurationName</key><string>Default Configuration</string>
+          <key>UISceneDelegateClassName</key><string>$(PRODUCT_MODULE_NAME).SceneDelegate</string>
+          <key>UISceneStoryboardFile</key><string>Main</string>
+        </dict>
+      </array>
+    </dict>
+  </dict>
 </dict></plist>
```

(If the project generates Info.plist from build settings, add the same keys through the target's Info tab instead.)

### 3.2 New `SceneDelegate.swift`

```diff
+import UIKit
+
+class SceneDelegate: UIResponder, UIWindowSceneDelegate {
+    var window: UIWindow?   // set by UIKit from UISceneStoryboardFile
+
+    // Cold start: app was launched by the social-login redirect
+    func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
+               options connectionOptions: UIScene.ConnectionOptions) {
+        guard scene is UIWindowScene else { return }
+        connectionOptions.urlContexts.forEach { _ = SocialLogin.shared.handle($0.url) }
+    }
+
+    // Warm: app was running when the redirect came back
+    func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
+        URLContexts.forEach { _ = SocialLogin.shared.handle($0.url) }
+    }
+}
```

### 3.3 `AppDelegate.swift`

```diff
+import UIKit
+
 @main
 class AppDelegate: UIResponder, UIApplicationDelegate {
-    var window: UIWindow?
-    func application(_ app: UIApplication, open url: URL, options: [UIApplication.OpenURLOptionsKey: Any] = [:]) -> Bool {
-        return SocialLogin.shared.handle(url)   // third-party social login callback
-    }
+    func application(_ application: UIApplication,
+                     configurationForConnecting connectingSceneSession: UISceneSession,
+                     options: UIScene.ConnectionOptions) -> UISceneConfiguration {
+        UISceneConfiguration(name: "Default Configuration", sessionRole: connectingSceneSession.role)
+    }
 }
```

Notes:
- `import UIKit` is missing from the fixture file. Your real file probably has it. Add it if it doesn't.
- If the `SocialLogin` SDK's docs say it needs `sourceApplication` or other options, pass `$0.options.sourceApplication` from `UIOpenURLContext`. Also check whether the SDK has a newer version with a scene-aware handler. Upgrading the SDK needs your approval, so it is not part of this diff.
- If other code uses `(UIApplication.shared.delegate as? AppDelegate)?.window`, it now needs the scene's window. The grep in section 2 will find it.

- **Build number:** the new build number must be higher than any build already uploaded for version 3.0. `CFBundleVersion` is not in the fixture `Info.plist`. Check that it is set (it may come from build settings).
