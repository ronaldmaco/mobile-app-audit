# App Review rejection: "app does not open"

## Bottom line

I can't say the build is ready to resubmit yet. I have a strong lead on the cause, but I couldn't confirm it because I had no device, simulator, crash log or rejection text. Below are the likely cause, a proposed fix as diffs (I haven't applied it), and the checks to run before you resubmit.

**What I reviewed:** `AppDelegate.swift`, `Info.plist` and `notes.md`, which is all of the code I was given. I had no project file, no other source files, no crash reports and no copy of the rejection message.

## Why it works on your phone but not for App Review

Your phone and App Review are not running the same app:

- **Your phone** has last month's build, made with the **previous Xcode**.
- **App Review** got the new build, made with the **newest Xcode and iOS SDK** (from `notes.md`).

So "it works on my phone" doesn't tell us anything about the build that was rejected. What changed between the two builds is the SDK. Install the rejected build itself (through TestFlight) before drawing any conclusions.

## Most likely cause: the app still uses the old launch model, which the new SDK no longer supports

The code shows the app uses the old app-delegate lifecycle, with no scenes:

- `Info.plist` has `UIMainStoryboardFile = Main` but no `UIApplicationSceneManifest`.
- `AppDelegate` owns `var window: UIWindow?` and there is no `SceneDelegate`.

At WWDC 2025 Apple said the iOS 26 SDK was the last one that would launch apps without the UIScene lifecycle. For apps built with the SDK after it, adopting UIScene is required, and apps that haven't adopted it **will not launch**. Under the iOS 26 SDK this was only a console warning, which fits your app working with the previous Xcode. Today's newest Xcode ships the next SDK, where it is enforced. That matches the report: the app does not open, and only on the build made with the new Xcode.

**Confidence:** high that this is a real problem in this build, and medium that it is the specific reason the reviewer saw. I haven't seen the crash log, so there could be a second cause, for example a third-party SDK that is incompatible with the new iOS.

### Side effect to handle in the same change: the social-login callback

Once the app uses scenes, iOS **stops calling** `application(_:open:options:)` on the AppDelegate. Incoming URLs go to the `SceneDelegate` instead:

- `scene(_:openURLContexts:)` when the app is already running.
- `connectionOptions.urlContexts` in `scene(_:willConnectTo:options:)` when the URL cold-launches the app.

If you only add a scene manifest, the app will launch again but the `sociallogin-demo://` callback will silently stop working. Login will look like it "does nothing", which is a likely cause of a second rejection under guideline 2.1. The diff below handles both cases.

## Proposed changes (not applied)

### 1. `Info.plist`: adopt scenes and keep the Main storyboard

```diff
 <?xml version="1.0" encoding="UTF-8"?>
 <plist version="1.0"><dict>
   <key>CFBundleShortVersionString</key><string>3.0</string>
-  <key>UIMainStoryboardFile</key><string>Main</string>
+  <key>UIApplicationSceneManifest</key>
+  <dict>
+    <key>UIApplicationSupportsMultipleScenes</key><false/>
+    <key>UISceneConfigurations</key>
+    <dict>
+      <key>UIWindowSceneSessionRoleApplication</key>
+      <array>
+        <dict>
+          <key>UISceneConfigurationName</key><string>Default Configuration</string>
+          <key>UISceneDelegateClassName</key><string>$(PRODUCT_MODULE_NAME).SceneDelegate</string>
+          <key>UISceneStoryboardFile</key><string>Main</string>
+        </dict>
+      </array>
+    </dict>
+  </dict>
   <key>CFBundleURLTypes</key><array><dict><key>CFBundleURLSchemes</key><array><string>sociallogin-demo</string></array></dict></array>
 </dict></plist>
```

`UISupportsMultipleScenes = false` keeps today's single-window behaviour, so the design doesn't change.

### 2. New `SceneDelegate.swift`

```diff
+import UIKit
+
+class SceneDelegate: UIResponder, UIWindowSceneDelegate {
+    var window: UIWindow?   // set automatically from UISceneStoryboardFile ("Main")
+
+    func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
+               options connectionOptions: UIScene.ConnectionOptions) {
+        // Cold launch via the social-login callback URL
+        if let url = connectionOptions.urlContexts.first?.url {
+            _ = SocialLogin.shared.handle(url)
+        }
+    }
+
+    func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
+        // App already running / in background
+        guard let url = URLContexts.first?.url else { return }
+        _ = SocialLogin.shared.handle(url)
+    }
+}
```

### 3. `AppDelegate.swift`: stop owning the window

```diff
+import UIKit
+
 @main
 class AppDelegate: UIResponder, UIApplicationDelegate {
-    var window: UIWindow?
-    func application(_ app: UIApplication, open url: URL, options: [UIApplication.OpenURLOptionsKey: Any] = [:]) -> Bool {
-        return SocialLogin.shared.handle(url)   // third-party social login callback
-    }
+    func application(_ application: UIApplication,
+                     didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
+        // Keep any SDK setup that already lives here (e.g. SocialLogin configuration).
+        return true
+    }
+
+    func application(_ application: UIApplication,
+                     configurationForConnecting connectingSceneSession: UISceneSession,
+                     options: UIScene.ConnectionOptions) -> UISceneConfiguration {
+        UISceneConfiguration(name: "Default Configuration", sessionRole: connectingSceneSession.role)
+    }
 }
```

(The fixture has no `import UIKit` and no `didFinishLaunching`. I expect the real file has more code than I was shown. Keep everything that is there and only move the window and URL handling.)

### 4. Code I couldn't see that will also need to change

Search the rest of the project for the following. Any of these can crash or show a blank screen once the AppDelegate no longer owns the window:

- `(UIApplication.shared.delegate as? AppDelegate)?.window` or `appDelegate.window`: replace with the scene's window, for example `view.window` or `(UIApplication.shared.connectedScenes.first as? UIWindowScene)?.keyWindow`.
- `UIApplication.shared.keyWindow` or `UIApplication.shared.windows`: deprecated, and often `nil` at launch under scenes.
- `applicationDidBecomeActive`, `applicationWillResignActive`, `applicationDidEnterBackground` and `applicationWillEnterForeground` in the AppDelegate: under scenes these are replaced by the `sceneDidBecomeActive` family. Move any logic that matters, such as token refresh, analytics or a lock screen.
- The SocialLogin SDK: check its release notes for (a) support for the new iOS SDK and (b) a scene-based URL handler. Some SDKs require their own scene API instead of the AppDelegate one. Update the SDK if the version you ship predates the new Xcode.

## Other points to check before resubmitting

1. **`sociallogin-demo` URL scheme.** This looks like a placeholder copied from an SDK sample. If your provider console has a different redirect scheme registered (for example a client-ID-based scheme), login will never return to the app. Confirm it matches the provider configuration for the **production** app.
2. **Build number.** App Store Connect rejects a resubmission that reuses a build number. Increment `CFBundleVersion`, which isn't in this plist fragment. Version 3.0 can stay.
3. **Launch screen.** `UILaunchStoryboardName` is missing from the fragment. Make sure the real plist has it.
