# Promoted card: wrong item on tap, and Home crash on open

**Scope:** I reviewed the code only, in `PromotedItemService.kt` (the only file in the excerpt). It does not build, and there is no device, backend, crash log or git history. So both causes below come from reading the code. I have not reproduced either one on a device. Both reports trace back to the same line:

```kotlin
val promotedItem: Item
    get() = catalog.promotable.filterNot { owned.contains(it.id) }.random()
```

## 1. The card opens a different item than it shows (confirmed in code)

**Cause:** `promotedItem` is a property with a custom getter, not a stored value, so each read runs the getter again and calls `random()` again. `bindPromoted()` reads it twice:

- `PromotedItemService.kt:8` sets the title from one random pick.
- `PromotedItemService.kt:9` reads `service.promotedItem.id` inside the click listener. That runs when the user taps, and it makes a new random pick.

So the item opened is chosen separately from the item shown. It only matches by chance: if N items are eligible, the chance of a match is about 1/N. That fits the report of "some users": anyone with just one eligible item always gets the right one.

**How to check:** On a test account with at least 3 eligible items, open Home, note the title and tap the card. Repeat a few times. Or add a log line inside the getter: it will print twice per bind, with different ids.

## 2. Home crashes on open (very likely cause)

**Cause:** Kotlin's `Collection.random()` throws `NoSuchElementException("Collection is empty.")` when the list is empty. The list is empty when:

- the user already owns every promotable item. This fits "one user": a heavy user or collector who owns everything;
- `catalog.promotable` is empty, for example because the catalog has not loaded yet on a cold start, or the backend returned no promotable items.

`bindPromoted()` runs when Home opens, and nothing catches the exception, so Home crashes on open. It will keep crashing for that user every time, because the data does not change.

**How to check:** Ask for that user's crash trace and look for `NoSuchElementException: Collection is empty` coming from `PromotedItemService.getPromotedItem` / `HomeFragment.bindPromoted`. To reproduce, use a test account that owns all promotable items, or stub `catalog.promotable` as empty, then open Home.

**Assumptions:** `Catalog.promotable` is a `List`/`Collection`, `OwnedItems.contains` is a plain membership check, and `bindPromoted()` runs during Home's view setup. These are not in the excerpt.

## Fix (without changing the design)

Pick the item once, allow "nothing to promote", and use the same object for the title and the tap:

```kotlin
class PromotedItemService(private val catalog: Catalog, private val owned: OwnedItems) {
    fun pickPromotedItem(): Item? =
        catalog.promotable.filterNot { owned.contains(it.id) }.randomOrNull()
}

class HomeFragment : Fragment() {
    fun bindPromoted() {
        val item = service.pickPromotedItem()
        if (item == null) {
            promotedCard.isVisible = false   // or keep the existing empty/placeholder state
            return
        }
        promotedCard.isVisible = true
        promotedCard.title.text = item.title
        promotedCard.setOnClickListener { openItem(item.id) }
    }
}
```

Notes:
- Changing the property to a function makes it clear that each call returns a new random pick, so nobody reads it twice by mistake again.
- If the pick should stay the same across rotation or when the user returns to Home, store the chosen id in the ViewModel or saved state, not in the Fragment.
- If the catalog can still be loading when Home binds, call `bindPromoted()` again once it has loaded, so the card does not stay hidden.

## Regression tests to add

- A unit test: with several eligible items, the item passed to `openItem` has the same id as the displayed title's item. Use a seeded or injected `Random` so the test is deterministic.
- A unit test: when every promotable item is owned, and when `promotable` is empty, `pickPromotedItem()` returns `null` and nothing throws.
- A manual or UI test: log in as a user who owns every promotable item, open Home, and check there is no crash and the card is hidden.
