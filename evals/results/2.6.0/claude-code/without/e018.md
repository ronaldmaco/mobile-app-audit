# Will the app keep working, and stay updatable on Google Play, for 12 months if nothing changes?

**Short answer: no, on both counts.**

- **Updatable on Google Play:** this has **already** stopped. You cannot publish an update today without first raising `targetSdk`.
- **Keeps working:** the app has **one certain crash** on a fixed date (**1 January 2027, about 6 weeks away**) and **one likely full outage** around **early February 2027** (certificate renewal against a pinned key). Two dependencies also lose their support during the window.

Based on: `app/app/build.gradle.kts`, `PromoBanner.kt`, `network_security_config.xml`, `maintenance-notes.md`, and Google Play's official target API page (checked 2026-11-17). I could not build or run the app, so nothing here was tested on a device. Each item below says how to confirm it.

---

## Timeline (today = 2026-11-17)

| When | What happens if you change nothing | Severity |
|---|---|---|
| **Already true** (since 31 Aug 2026, extension ended 1 Nov 2026) | Play rejects **every update** because `targetSdk = 34` and updates must target API 36. New users on Android 15 and 16 phones can no longer find or install the app. | Blocker for any release |
| **1 Jan 2027** | `PromoBanner.bannerText()` throws on every Home screen `onResume`. **The app crashes on launch for 100% of users.** | Critical, certain |
| **On or before 2 Feb 2027** | The server certificate is renewed. If the hosting provider issues a **new key** (your notes say it may), the single pin no longer matches and **every API call fails** on Android 7+. | Critical, likely |
| **30 Jun 2027** | paylib 3.x stops getting fixes. Version 4 needs `minSdk 24`, so you drop Android 6 users. | High (payments) |
| **Ongoing** | chartkit has been archived since 2021: no fixes, and nothing guarantees it works with the newer target SDK that Play now requires. | Medium, blocks the upgrade |
| **Likely Aug 2027** (not announced yet) | Google usually raises the target level every August. Expect API 37 for updates and API 36 for existing apps. **Not verified**: the official page lists no 2027 date yet. | Planning |

The bad part is the combination. **The crash on 1 Jan 2027 needs an update to fix, and you cannot ship an update until the `targetSdk` work is done.** So the `targetSdk` upgrade is not optional "maintenance". It is the critical path to shipping the crash fix in time. Start now.

## 1. Google Play: you can no longer ship updates

**Evidence:** `build.gradle.kts` has `compileSdk = 34`, `targetSdk = 34`.

**Rule** (official: Google Play Console Help, "Target API level requirements for Google Play apps", support.google.com/googleplay/android-developer/answer/11926878):
- New apps and **app updates** must target **Android 16 (API 36)** from **31 Aug 2026**. The optional extension ran to **1 Nov 2026** and has expired.
- **Existing apps** must target **API 35+** from 31 Aug 2026 to stay available to new users. Apps below that are only offered to devices running Android at or below their target level.

**What that means for you:**
- Users who already installed the app keep it, and it keeps running on their phones (until the dates below).
- New users on Android 15/16 devices cannot install it. That is a growing share of the market.
- Any upload targeting 34 will be rejected.

**How to verify:** Play Console, **Policy status** page and **Inbox/Notifications** (Google posts a target API warning there). Or upload a build to the internal testing track and look at the error.

**Fix:** set `compileSdk = 36` and `targetSdk = 36`, update AGP/Kotlin/AndroidX to versions that support API 36, then test the behaviour changes:
- **Android 15 (35):** edge-to-edge is enforced. Expect content under the status and navigation bars on every screen.
- **Android 16 (36):** the edge-to-edge opt-out is removed, and large screens ignore orientation and resizability restrictions.
- **16 KB memory pages:** since 1 Nov 2025, updates targeting Android 15+ must support 16 KB page sizes **if the app ships native `.so` libraries**. Check whether chartkit or paylib bundle any: open the release APK/AAB in Android Studio's **APK Analyzer** and look for `lib/`. Android Studio flags libraries that are not 16 KB aligned.

## 2. Certain crash on 1 January 2027 (PromoBanner)

**Evidence:** `PromoBanner.kt`:

```kotlin
private val PROMO_END: LocalDate = LocalDate.of(2026, 12, 31)
...
if (today.isAfter(PROMO_END)) {
    throw IllegalStateException("Promo config missing for $today")
}
```

`maintenance-notes.md`: `bannerText()` is called from the Home screen's `onResume`.

From 1 Jan 2027 (device local date) the exception is thrown on every Home `onResume`. An uncaught exception in a lifecycle callback kills the process, so **the app crashes on opening for every user, every time**. Users with a wrong device clock hit it earlier or later. Also, `LocalDate` (java.time) on API 23–25 relies on core library desugaring. Check that `coreLibraryDesugaringEnabled` is set somewhere, or Android 6/7 users may already be crashing here (not verifiable from these files).

**How to verify without waiting:** a unit test calling `PromoBanner.bannerText(LocalDate.of(2027, 1, 1))` throws. On a device or emulator, set the date to 1 Jan 2027 and open the app.

**Fix (small):** never throw from UI code because of a date. After the end date, return no banner (`null` or empty, and hide the view), or load the promo from remote config with a safe default. Add the unit test above. Ship this in the same release as the `targetSdk` upgrade, **before 1 Jan 2027**. Leave time for Play review and for users to update. Users who do not update before 1 Jan will still crash until they do, so aim for mid-December at the latest.

## 3. Likely full outage around 2 February 2027 (certificate pinning)

**Evidence:**
- `network_security_config.xml` pins `api.example.com` (and subdomains) to **one** SHA-256 pin, described as "the current server certificate's public key". There is **no backup pin**. The `pin-set expiration="2028-01-15"`, so pinning stays enforced for the whole 12-month window.
- `maintenance-notes.md`: the certificate expires **2 Feb 2027**. The provider renews automatically and **may issue a new key**.

If the renewed certificate uses a new key pair, no certificate in the chain matches the pin. **Every HTTPS call to the API fails on Android 7+**, which is almost all users. The app stays installed but stops working. The renewal can happen **before** 2 Feb (auto-renewal often runs weeks early), so the risk window may open in January. Note: network security config pinning is not applied on Android 6 (API 23), so those users are not affected by this item.

**How to verify:**
- Compare the pin with the live key now: `openssl s_client -connect api.example.com:443 -servername api.example.com </dev/null 2>/dev/null | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64`
- Ask the hosting provider whether renewal **reuses the key** and when it runs.
- Check whether the pin is the leaf key or an intermediate/root CA key. Pinning an intermediate or root survives leaf renewal.

**Fix (pick one, in the same release as items 1 and 2):**
- Add **backup pins**: the intermediate CA key and/or a pre-generated spare key. Android documentation recommends always including a backup pin.
- Or arrange with the provider to **keep the same key** at renewal, or to let you supply the CSR/key.
- Or remove pinning if the threat model does not need it.

In every case, the release with the extra pins must be **installed by users before the certificate changes**. Users still on old builds will break. Another reason to ship in December.

## 4. Dependencies losing support

**paylib 3.8.0** (`build.gradle.kts`). Per the vendor's support page (quoted in your notes, not verified by me), major version 3 gets fixes **until 30 Jun 2027**, inside your 12-month window. It will not stop working on that date by itself. But after that, any security fix, payment-network change or Play/Android incompatibility will not be fixed for v3. Version 4 requires **`minSdk 24`**, so moving to it drops Android 6.0 (API 23) devices. Check in Play Console (**Statistics / Android version**) how many active users are on Android 6. It is usually a very small share. Plan the v4 migration for H1 2027, not after the cut-off. **Verify:** the vendor's support/EOL page and the v4 migration guide; confirm whether v3.8.0 already supports API 36.

**chartkit 2.3.1**. The repository is archived, last release 2021, README says unmaintained. Nothing changes in it on a date, but it is the most likely thing to **break when you raise `targetSdk` to 36**: edge-to-edge, 16 KB native alignment, and removed or deprecated APIs. Any bug or security issue will never be fixed. **Verify:** after the `targetSdk` bump, open every chart screen on an Android 16 emulator, and check APK Analyzer for native libs from it. **Plan:** replace it with a maintained chart library, or vendor the source into the repo so you can patch it.

**androidx.core 1.12.0** is old. Update it as part of the API 36 upgrade.

## What I recommend (minimum to "keep working" for 12 months)

**One release, shipped by mid-December 2026:**
1. `compileSdk`/`targetSdk` 36, plus toolchain updates and edge-to-edge/16 KB checks. *Unblocks Play.*
2. PromoBanner never throws after its end date, plus a unit test. *Prevents the 1 Jan crash.*
3. Backup pin(s), plus confirmation from the hosting provider about key reuse. *Prevents the February outage.*
4. Test chartkit screens on Android 15/16. Replace chartkit if it breaks.

**In H1 2027:**
5. Migrate paylib to v4 before 30 Jun 2027, and decide on dropping Android 6 (`minSdk 24`).
6. Replace chartkit if not done already.

**Around Aug 2027:** check the Play target API page for the next yearly requirement. Expect API 37 for updates (not announced yet, so unverified).

Your current "twice a year" release rhythm is enough **after** this catch-up, provided one of the two releases each year is timed before Google's August target-API deadline.
