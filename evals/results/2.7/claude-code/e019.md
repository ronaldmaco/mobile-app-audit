Run 2026-11-23. Claude Code, Opus 5.5 (`claude-opus-5-5`), effort medium, 60-turn cap, 900 s timeout, same sandbox, prompt and fixture in both conditions. Skill at the commit in the run's repo state (no change to `skills/` since 2.6.2). 3 runs with the skill installed, 3 without, in a random order.

## Result

| Condition | Passed | Must items met | must_not hits |
|---|---|---|---|
| With the skill | 2/3 | 14/15 | 0 |
| Without the skill | 0/3 | 11/15 | 0 |

The skill loaded in all 3 runs where it was installed and in none of the others (`e019-runs.tsv`).

All six answers found the three causes and fixed them in code (must 2, 4). The difference is in must 5, the verification: the two passing answers give a check of both the server (exactly one note) and the screen after the return (the spinner ends, the editor closes), and say no device was run. The failing with-skill run gives device steps without saying what result to expect. Two runs without the skill give no verification; the third checks the screen but not the number of notes, and does not name the missing Idempotency-Key as the cause of the duplicate (must 1).

## How it was graded
Answers and diffs were relabelled A-F at random and graded by a second model that did not know the conditions (`e019-grades-blind.md`, mapping in `e019-blind-map.json`). The maintainer re-read the four failures and agrees with them.

The judge flagged two loose readings, applied the same way to all six: every answer derives the Idempotency-Key from the title and body (a retry without edits reuses it, an edit makes a new one), and five keep the pending result in the ViewModel and hand it to the screen in `onStart` instead of a StateFlow. Both were graded as met.

## Limits
- 3 runs per condition. 2/3 vs 0/3 is not a statistically significant difference; read it as a direction, not a measured effect.
- No real case behind it. The fixture and criteria were written by the maintainer's agent after the device condition was added to `references/device-testing.md` (2.6.2), so the criteria follow what the skill asks for, and the eval may favour it.
- Code-reading only: no device or emulator was available to the agent, so no answer could run the check it described.
